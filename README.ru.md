# ocx-lan-filter · LAN Model Proxy

[English](README.md) · **Русский**

Отдайте **одну выбранную модель** из локального [OpenCodex (`ocx`)](https://github.com/lidge-jun/opencodex) другим устройствам
в домашней сети по ключу доступа, не раскрывая остальное содержимое `ocx`.
Небольшое приложение в строке меню macOS позволяет управлять этим без терминала.

```
другое устройство ──HTTP──▶ <IP_MAC>:10200 (ocx-lan-filter) ──▶ 127.0.0.1:10100 (ocx) ──▶ провайдер
                            проверка ключа, алиас, белый список   только loopback
```

`ocx` по-прежнему слушает только `127.0.0.1`. Переводить его на `0.0.0.0` не нужно, поэтому локальные инструменты
(codex, opencode, omp) продолжают работать без токена.

## Зачем отдельный прокси

- Ключи самого `ocx` (`ocx access key create`) **не умеют ограничивать модели**: любой ключ видит весь каталог.
- При `hostname: 0.0.0.0` `ocx` требует токен от всех клиентов, в том числе локальных.
- Фильтр решает оба пункта: в сеть смотрит только он, и он пропускает ровно те алиасы, которые вы задали.

## Возможности

- Несколько **эндпоинтов**: у каждого свой порт, область доступа (вся сеть или только этот Mac), ключ и набор **алиасов**
  (алиас → реальная модель `ocx`). Клиент всегда просит алиас, а модель за ним можно менять в любой момент.
- Смена модели применяется **мгновенно**: без перезапуска и без перенастройки клиентов.
- Строгий белый список: `GET /v1/models`, `GET /healthz`, `POST /v1/chat/completions`, `POST /v1/responses`. Всё остальное даёт 404,
  любая модель кроме заданных алиасов даёт 403, отсутствующий или неверный ключ даёт 401.
- Работает стриминг. Только стандартная библиотека Python, зависимостей нет.
- Нативное **приложение в строке меню** (SwiftUI, стиль Apple Liquid Glass на macOS 26, запасной вариант на материалах для macOS 14–15)
  и CLI `lanmodel`.
- Закрытие приложения прокси **не останавливает**: он работает как агент `launchd`.
- Интерфейс приложения на **русском и английском**. По умолчанию язык берётся из системы (русский, только если он основной язык macOS, иначе английский); в **Настройках** его можно переключить вручную.

## Требования

- macOS 14 или новее (стиль Liquid Glass нужен macOS 26).
- Python 3 (`python3` с python.org, из Homebrew или из Xcode Command Line Tools).
- Запущенный [OpenCodex](https://github.com/lidge-jun/opencodex) на `127.0.0.1:10100` (порт по умолчанию).

## Установка

### Вариант А: приложение (рекомендуется)

1. Скачайте `LAN-Model-Proxy-<версия>.dmg` из [последнего релиза](../../releases/latest).
2. Откройте DMG и перетащите **LAN Model Proxy** в **Программы** (Applications).
3. Приложение подписано ad-hoc и не нотаризовано, поэтому macOS заблокирует первый запуск. Сделайте одно из двух:
   - откройте **Системные настройки → Конфиденциальность и безопасность**, прокрутите вниз и нажмите **Всё равно открыть** для LAN Model Proxy;
   - либо один раз выполните `xattr -dr com.apple.quarantine "/Applications/LAN Model Proxy.app"`.
4. Запустите приложение. В строке меню появится значок сети, нажмите на него.
5. Если в окне написано **«Сервис не установлен»**, нажмите **Установить**. Фильтр копируется в
   `~/.local/share/ocx-lan-filter/`, создаётся ключ доступа и конфиг по умолчанию, регистрируется сервис `launchd`.
   Моделью по умолчанию станет первая, которую сейчас отдаёт `ocx`. Сразу смените её (см. ниже).

### Вариант Б: из исходников

```sh
git clone https://github.com/IMPOSTOR15/ocx-lan-filter.git
cd ocx-lan-filter
./install.sh                           # сервис и CLI lanmodel (~/.local/bin)
cd menubar
swift test                             # по желанию
./scripts/build_app.sh                 # собирает menubar/build/LAN Model Proxy.app
./scripts/install_app.sh               # копирует в ~/Applications и запускает
./scripts/make_dmg.sh                  # по желанию: универсальная сборка в DMG
```

`install.sh` идемпотентен: существующие ключ и конфиг он не перезаписывает, поэтому его безопасно запускать повторно после обновления.
Чтобы пользоваться `lanmodel`, добавьте `~/.local/bin` в `PATH`.

## Как пользоваться приложением

Всё управление в одном окне под значком в строке меню (без отдельных окон и диалогов).

- **Список эндпоинтов.** Карточка на каждый эндпоинт: статус, URL и каждый алиас с моделью за ним. Нажмите на капсулу с моделью,
  чтобы выбрать другую из каталога `ocx` (есть поиск). Изменение применяется сразу.
- **Кнопки карточки.** Копировать URL, копировать готовый `curl`, копировать ключ (из буфера обмена очистится через 60 с),
  реальный тестовый запрос через эндпоинт, **Изменить**.
- **Форма эндпоинта (＋ или «Изменить»).** Название, переключатель «Включён», доступ (**вся сеть** `0.0.0.0` / **этот Mac** `127.0.0.1`), порт,
  ключ доступа (показать на 15 с, копировать, сменить), алиасы с длиной контекста, удаление.
- **Нижняя панель.** Настройки, перезапуск сервиса, открыть лог, выход.
- **Настройки.** Язык (Как в системе / Русский / English, применяется сразу), автозапуск при входе, версия приложения.
- Плашка с предупреждением появляется, если сервис не установлен, устарел или остановлен, конфиг невалиден или модели больше нет в каталоге `ocx`.
  Где возможно, рядом есть кнопка исправления.

Ключ не пишется в логи и не показывается в интерфейсе без явного нажатия **«Показать»**.

## Как пользоваться CLI

```sh
lanmodel            # текущий алиас → модель
lanmodel list       # нумерованный список моделей, которые отдаёт ocx
lanmodel set 6      # переключить по номеру…
lanmodel set <id>   # …или по точному id
lanmodel test       # реальный запрос через фильтр
lanmodel restart    # перезапуск сервиса (нужен только после правки filter.py)
```

## Подключение клиента

URL и ключ возьмите в приложении (кнопки копирования) или из файлов ниже. Подойдёт любой OpenAI-совместимый клиент.

| Параметр | Значение |
|---|---|
| Base URL | `http://<IP_MAC>:10200/v1` (показан в приложении; IP смотрите в Системных настройках → Wi-Fi → Подробнее) |
| API-ключ | содержимое файла ключа эндпоинта |
| Заголовок | `Authorization: Bearer <ключ>` (также `x-api-key` или `x-opencodex-api-key`) |
| Модель | алиас, по умолчанию `local-llm`; любое другое значение даёт 403 |
| Протокол | OpenAI Chat Completions со стримингом; `/v1/responses` тоже проксируется |

```sh
KEY=$(cat ~/.local/share/ocx-lan-filter/key)
curl -s http://<IP_MAC>:10200/v1/chat/completions \
  -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
  -d '{"model":"local-llm","messages":[{"role":"user","content":"2+2?"}],"max_tokens":100}'
```

Готовый промпт, который можно отдать ИИ-агенту на другом устройстве для настройки opencode, Codex или другого клиента:
[docs/client-setup-prompt.md](docs/client-setup-prompt.md).

## Что пропускает фильтр

| Запрос | Результат |
|---|---|
| без ключа или с неверным ключом | 401 |
| `GET /v1/models` | 200, только алиасы этого эндпоинта |
| `GET /healthz` | 200, алиас и текущая реальная модель |
| `POST /v1/chat/completions`, `POST /v1/responses` с алиасом в `model` | проксируется в `ocx` с подменой модели |
| те же пути с любым другим `model` (включая настоящее имя) | 403 |
| любые другие пути (`/api/keys`, админка `ocx` и т.д.) | 404 |

## Где что лежит

| Что | Путь |
|---|---|
| Рабочая копия фильтра | `~/.local/share/ocx-lan-filter/filter.py` |
| Конфиг (эндпоинты, алиасы, модели) | `~/.local/share/ocx-lan-filter/config.json` |
| Статус слушателей (пишет фильтр) | `~/.local/share/ocx-lan-filter/runtime.json` |
| Ключ эндпоинта по умолчанию | `~/.local/share/ocx-lan-filter/key` (права 600) |
| Ключи дополнительных эндпоинтов | `~/.local/share/ocx-lan-filter/keys/<id>.key` (права 600) |
| Лог | `~/.local/share/ocx-lan-filter/filter.log` |
| launchd-сервис | `~/Library/LaunchAgents/com.local.ocx-lan-filter.plist` (label `com.local.ocx-lan-filter`) |
| CLI | `~/.local/bin/lanmodel` |

Рабочая копия отделена от исходников намеренно: launchd-агентам на macOS часто закрыт доступ к `~/Documents` (TCC).
После правки `filter.py` в исходниках снова запустите `./install.sh`.

`config.json` v2 описывает upstream и эндпоинты. Его пишет приложение, а фильтр перечитывает раз в секунду (поднимает новые порты, закрывает убранные).
Невалидный конфиг отклоняется целиком, продолжает работать последний рабочий, причина видна в `runtime.json` и в приложении.
Старый формат `{"upstream_model": "…"}` читается как эндпоинт `default` с алиасом `local-llm`.
Схема и правила валидации: раздел 4.1 в [docs/menubar-app/PLAN.md](docs/menubar-app/PLAN.md).

## Типовые операции

```sh
# сменить ключ (старый перестаёт работать сразу, обновите клиентов)
python3 -c "import secrets;print('lan_'+secrets.token_urlsafe(32),end='')" > ~/.local/share/ocx-lan-filter/key
chmod 600 ~/.local/share/ocx-lan-filter/key

# статус и логи
launchctl print gui/$(id -u)/com.local.ocx-lan-filter | grep -E "state|pid"
tail -f ~/.local/share/ocx-lan-filter/filter.log

# удаление
launchctl bootout gui/$(id -u)/com.local.ocx-lan-filter
rm ~/Library/LaunchAgents/com.local.ocx-lan-filter.plist
rm -r ~/.local/share/ocx-lan-filter ~/.local/bin/lanmodel
```

## Безопасность

- Трафик идёт по HTTP без шифрования. Для доверенной домашней сети это допустимо, для публичного Wi-Fi нет. Иначе поставьте перед фильтром TLS-туннель.
- Фильтр не ограничивает число запросов и не считает расход: всё, что проходит, тратит квоту аккаунтов за `ocx`.
- Закрепите IP Mac на роутере (резервирование DHCP). «Вращающийся» частный адрес Wi-Fi в macOS меняет MAC и ломает резервирование,
  для этой сети выберите «Фиксированный» или «Выкл.».
- Хосты слушателей ограничены `0.0.0.0` и `127.0.0.1`. Ключи сравниваются за постоянное время и не логируются.
- Для эндпоинтов, которые не должны быть видны из сети, выбирайте «Этот Mac».

## Если что-то не работает

| Симптом | Причина / решение |
|---|---|
| Клиенты получают таймаут | Mac спит или у него сменился IP. Проверьте URL в приложении и резервирование на роутере. |
| 502 `upstream unavailable` | `ocx` не запущен на `127.0.0.1:10100`. Запустите его (`ocx start`). |
| 401 | Нет ключа или он неверный; возможно, ключ сменили. |
| 403 | В `model` указан не алиас этого эндпоинта. |
| «Сервис не установлен» не пропадает | Проверьте, что есть `python3` (`python3 --version`). Ошибка установки показана в приложении. |
| Модель подсвечена оранжевым | Её больше нет в каталоге `ocx`. Выберите другую. |
| `lanmodel: command not found` | Добавьте `~/.local/bin` в `PATH`. |
| Приложение не открывается | См. шаг «Всё равно открыть» / `xattr` в разделе [Установка](#установка). |

## Разработка

```sh
python3 -m unittest discover -s tests -t tests     # фильтр, CLI и общие фикстуры валидации
cd menubar && swift test                           # логика и контрактные тесты с реальным filter.py
```

Структура: `filter.py` (data plane), `lanmodel` (CLI), `install.sh` + `launchd/` (сервис), `menubar/` (Swift-пакет: `LanModelCore` логика,
`LanModelBar` интерфейс), `tests/`, `docs/`. Приложение и фильтр общаются только файлами (`config.json`, `runtime.json`).
Правила валидации продублированы в `filter.py` и `Validator.swift` и используют общие `tests/fixtures/validation.json`.
